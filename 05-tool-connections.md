# Module 05 — Tool connections

## Goal

Bring in the information needed for a decision without giving a workflow more access than it needs.

## Practice

For every proposed connection, document:

- the question it answers;
- the minimum data it needs;
- whether it reads, writes, or can trigger an external action;
- who approves its use;
- how its output is checked.

Start with read-only access to a documentation source, issue tracker, or source repository. Add write access only after the review path is clear.

## Check

If you cannot describe the connection’s permission in one sentence, its scope is too broad.

## Next step

Place a quality gate after the connection’s output is used.
