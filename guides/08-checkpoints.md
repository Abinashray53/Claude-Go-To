# Module 08 — Checkpoints

## Goal

Make ambitious work reversible without making every change timid.

## Practice

Before a substantial refactor:

1. Record the starting behavior and relevant tests.
2. Create a named branch or commit.
3. Break the work into reviewable milestones.
4. Test after each milestone, not only at the end.
5. Note the last known-good state.

A checkpoint is useful only when you can restore it quickly. Test restoration on a small change before relying on it for a large one.

## Next step

Use checkpoints as the control points in a broader delivery workflow.
